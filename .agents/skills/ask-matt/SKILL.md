# ask-matt

Read `/AGENTS.md`, `/CONTEXT.md`, `docs/agents/modes.md`, and the task's durable artifacts first.

Route by uncertainty:
- unknown facts -> `research`;
- unresolved decisions -> `grill-with-docs`;
- huge/foggy work -> `wayfinder`;
- settled direction -> `to-spec`;
- multi-session work -> `to-tickets`;
- implementation -> `implement`;
- bug -> `diagnosing-bugs`;
- incoming issue/PR -> `triage`;
- architecture health -> `improve-codebase-architecture`;
- review -> `code-review`;
- context transfer -> `handoff`;
- human-only secrets/setup -> `wizard`.

Do not route around Woyengi's authority, history, or verification constraints. If a skill conflicts with the Constitution, the skill loses.

For product engineering, prefer one end-to-end governed vertical slice over broad speculative breadth. For RL work, define hidden ground truth, environment dynamics, verifier, and leakage controls before optimization. For research, require a falsifiable hypothesis and baseline before interpreting results.
